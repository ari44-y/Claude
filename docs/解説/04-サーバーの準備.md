# 解説 04：サーバーの準備（手順書）

Phase 1 の手順3の残り。Ubuntu Server のノートパソコンで、クロコさんを iPhone から開けるようにする。
**ここに書いたコマンドは、Mac から ssh でサーバーに入って実行する。** 1回だけ行う作業がほとんど。

前提（確認済み）：Ubuntu Server・Docker・Tailscale がサーバーに入っている。CPU は x86_64。Mac から ssh で入れる。

```
iPhone（Tailscale）──HTTPS──▶ サーバーの Tailscale（tailscale serve）
                                  │
                                  ▼ 127.0.0.1:8000
                              Docker コンテナ kuroko-app ── /var/lib/kuroko（DB）
                                                              │ 毎日 3:30
                                                              ▼
                                                 systemd タイマー → backup.sh → /var/backups/kuroko
```

文中の `<ユーザー名>` はサーバーのログインユーザー名に置き換える。

---

## 1. 事前の確認

```bash
docker compose version     # 「Docker Compose version v2.x」と出れば OK
git --version
tailscale status           # このサーバーが一覧に出ていれば OK
```

### 1.1 sudo なしで docker を使えるようにする

```bash
groups                     # 一覧に docker があれば、この節は飛ばしてよい
sudo usermod -aG docker $USER
exit                       # 一度ログアウトして、ssh で入り直すと反映される
```

> **なぜ**：更新スクリプト（`update.sh`）を毎回 sudo で実行しなくて済むようにするため。
> docker グループの人は実質的に管理者と同じ権限を持つので、このサーバーにログインできるのが自分だけであることが前提。

### 1.2 Docker を OS の起動時に立ち上げる

```bash
sudo systemctl enable docker
systemctl is-enabled docker     # enabled と出れば OK
```

> **なぜ**：コンテナの `restart: unless-stopped` は「Docker が動いていれば、コンテナを自動で起動する」という設定。
> Docker 自体が起動しなければ、コンテナも起動しない。

### 1.3 sqlite3 を入れる（バックアップで使う）

```bash
sudo apt update && sudo apt install -y sqlite3
```

## 2. リポジトリを clone する

```bash
cd ~
git clone https://github.com/ari44-y/Claude.git
cd Claude
git log --oneline -3       # Mac で push した最新のコミットが出れば OK
```

> **リポジトリを非公開にした場合**：サーバーから読むための専用の鍵（デプロイキー）を作る。
> 1. サーバーで `ssh-keygen -t ed25519 -f ~/.ssh/kuroko_deploy -N ""`
> 2. `cat ~/.ssh/kuroko_deploy.pub` の内容を、GitHub のリポジトリの Settings → Deploy keys に登録する（「Allow write access」はオフ＝読み取り専用）
> 3. `~/.ssh/config` に次を書き、`git clone git@github-kuroko:ari44-y/Claude.git` で clone する
>    ```
>    Host github-kuroko
>      HostName github.com
>      IdentityFile ~/.ssh/kuroko_deploy
>    ```
> 既に https で clone している場合は `git remote set-url origin git@github-kuroko:ari44-y/Claude.git` で切り替える。

## 3. ふたを閉じてもスリープしないようにする

2 で clone したリポジトリに入っている設定ファイルを置く。

```bash
sudo mkdir -p /etc/systemd/logind.conf.d
sudo cp ~/Claude/deploy/systemd/logind-kuroko.conf /etc/systemd/logind.conf.d/
```

反映は 9 の再起動のときに行われる（その場で `systemctl restart systemd-logind` すると、ssh の接続が切れることがあるため）。

> **なぜ別ファイルにするか**：`/etc/systemd/logind.conf` を直接書き換えると、Ubuntu の更新でこのファイルが新しくなったときに、
> 自分の設定と衝突する。`logind.conf.d/` に置いたファイルは、本体の設定の上から追加で読み込まれる。

## 4. タイムゾーンを日本時間にする

```bash
sudo timedatectl set-timezone Asia/Tokyo
timedatectl                # Time zone: Asia/Tokyo になっていれば OK
```

> アプリとバックアップのタイマーは日本時間をそれぞれ明示しているので、これをしなくても動く。
> ログ（`journalctl` など）の時刻が日本時間になり、読みやすくなる。

## 7. iPhone から開けるようにする（Tailscale）

### 7.1 Tailscale の管理画面で HTTPS を有効にする（初回だけ）

ブラウザで https://login.tailscale.com/admin/dns を開き、次の2つを有効にする。

- **MagicDNS**：`<サーバー名>.<tailnet名>.ts.net` という名前でサーバーに接続できるようにする
- **HTTPS Certificates**：その名前の HTTPS の証明書を、Tailscale が自動で用意できるようにする

### 7.2 サーバーで tailscale serve を設定する

```bash
sudo tailscale serve --bg 8000
tailscale serve status
```

次のように出れば OK（この URL をメモしておく）。

```
https://<サーバー名>.<tailnet名>.ts.net (tailnet only)
|-- / proxy http://127.0.0.1:8000
```

| 部分 | 意味 |
|---|---|
| `serve` | Tailscale のネットワークの中だけに公開する（インターネットには公開しない。公開するのは `funnel` という別の機能） |
| `--bg` | 裏で動かし続ける。サーバーを再起動しても設定は残る |
| `8000` | `https://...ts.net` への接続を、`http://127.0.0.1:8000`（コンテナ）に中継する |

### 7.3 iPhone で開く

1. iPhone に Tailscale のアプリを入れ、同じアカウントでログインして接続する
2. Safari で、7.2 でメモした `https://<サーバー名>.<tailnet名>.ts.net` を開く
3. タスク画面が出て、ゴミ出しのタスクが表示されれば OK

> **ホーム画面への追加と通知は、Phase 1 の手順4（Web Push）で行う。** 通知を受け取るにはアプリの情報ファイル（manifest）と
> Service Worker が必要で、まだ作っていない。今ホーム画面に追加しても、ただのブックマークとして動く。

## 8. 毎日のバックアップを設定する

### 8.1 保存先を決める（今は仮）

保存先は未決（要件定義書 9章）。決まるまでは、初期値の `/var/backups/kuroko`（本体の中）に保存する。
**本体のストレージが壊れると、バックアップも一緒に失われる**ので、外付けストレージなどが決まったら設定を変える。

保存先や保存日数を変えるときは、`/etc/default/kuroko-backup` を作る。

```bash
# 例：外付けストレージに 30日分
sudo tee /etc/default/kuroko-backup > /dev/null <<'EOF'
KUROKO_BACKUP_DIR=/mnt/usb/kuroko-backup
KUROKO_BACKUP_KEEP_DAYS=30
EOF
```

### 8.2 まず手動で試す

```bash
cd ~/Claude
sudo ./deploy/backup.sh
ls -la /var/backups/kuroko/*/
```

「バックアップしました: /var/backups/kuroko/20261107-…」と出て、その中に `kuroko.db` があれば OK。

### 8.3 タイマーを登録する

```bash
cd ~/Claude
# @REPO@ をリポジトリの場所に置き換えて、systemd のフォルダに置く
sed "s|@REPO@|$PWD|" deploy/systemd/kuroko-backup.service | sudo tee /etc/systemd/system/kuroko-backup.service > /dev/null
sudo cp deploy/systemd/kuroko-backup.timer /etc/systemd/system/

sudo systemctl daemon-reload                        # 新しい設定ファイルを読み込ませる
sudo systemctl enable --now kuroko-backup.timer     # 有効にして（再起動後も）、今すぐ動かし始める
systemctl list-timers kuroko-backup.timer           # NEXT に次の 3:30 が出れば OK
```

サービスとして動くかも試す：

```bash
sudo systemctl start kuroko-backup.service
journalctl -u kuroko-backup.service -n 5            # 「バックアップしました」が出ていれば OK
```

| ファイル | 役割 |
|---|---|
| `kuroko-backup.service` | 「backup.sh を1回実行する」という仕事の定義 |
| `kuroko-backup.timer` | 「その仕事を毎日 3:30 に起動する」という予定の定義 |

cron でも同じことができるが、systemd タイマーには次の利点がある。

- `Persistent=true`：3:30 にサーバーが止まっていたら、次に起動したときに実行してくれる
- 実行結果が `journalctl` で見られる

## 10. ふだんの更新の流れ

```
Mac で開発 → git push → Mac から下のコマンド1つ
```

```bash
ssh <ユーザー名>@<サーバー名> '~/Claude/deploy/update.sh'
```

ssh の後ろにコマンドを書くと、サーバーに入ってそのコマンドだけ実行し、すぐ戻ってくる。

## 11. 困ったとき

| 症状 | 確かめること |
|---|---|
| iPhone で開けない | iPhone の Tailscale がオンか。サーバーで `tailscale serve status` と `curl http://127.0.0.1:8000/api/health` |
| 画面が古いまま | Safari を一度閉じて開き直す。サーバーで `git log -1` が最新か |
| コンテナが動いていない | `docker compose -f compose.prod.yaml ps -a` と `docker compose -f compose.prod.yaml logs --tail 50` |
| 更新後に起動しない | ログに alembic のエラーが出ていないか。直前のバージョンに戻すには `git checkout <前のコミット>` → `docker compose -f compose.prod.yaml up -d --build` |
| バックアップが動いたか | `journalctl -u kuroko-backup.service --since yesterday` |

### よく使うコマンド（`~/Claude` で）

```bash
docker compose -f compose.prod.yaml ps              # 状態
docker compose -f compose.prod.yaml logs -f         # ログを流し続ける（Ctrl+C で抜ける）
docker compose -f compose.prod.yaml restart         # 再起動
docker compose -f compose.prod.yaml exec app bash   # コンテナの中に入る
```
