## 3. 全体の形

```
【開発中】
 ブラウザ ──▶ Vite（:5173）── 画面のファイル（src/ をその場で変換して返す）
                 │
                 └─ /api/... だけ中継 ──▶ FastAPI（:8000）

【本番（サーバー）】
```

画面のコードは、どちらの場合も同じ `/api/tasks` を呼ぶ。開発中は Vite の proxy 設定が FastAPI に中継してくれるので、

```

              └─ TaskItem × n   ─ useToggleDone ─▶ PATCH /api/task-instances/{id}
```

## 4. 解説

### 4.1 TypeScript 5.9 にした経緯

Vite の公式テンプレートは TypeScript 7 を使う構成だった。しかし入れてみると、型を自動生成する openapi-typescript が次のエラーで止まった。

```
TypeError: Cannot read properties of undefined (reading 'createKeywordTypeNode')
```

TypeScript 7 は、本体が JavaScript から Go 言語に書き直された版で、とても速い。
その代わり、ほかのツールが TypeScript の機能を呼び出すための窓口（JavaScript の API）がまだない。
openapi-typescript はこの窓口を使って型のコードを組み立てているため、動かなかった。

「型の生成だけ TypeScript 5 を使う」設定も試したが、npm は peer dependency
（「このライブラリと一緒に、この版を使って」という指定）をプロジェクト全体で1つにそろえる決まりがあり、できなかった。
そこでプロジェクトの TypeScript を 5.9 にした。このアプリの規模では、型チェックの速さの差はほとんど感じない。

> **教訓**：ライブラリの最新版どうしが、まだ対応し合っていないことはよくある。
> エラーが出たら、`npm view <パッケージ名> peerDependencies` で、どの版と組み合わせる前提かを確かめる。

### 4.2 Tailwind CSS の読み方

Tailwind は、1つのクラスがだいたい1つの CSS に対応している。この画面で使っているものを抜き出すと次のとおり。

| クラス | CSS | 意味 |
|---|---|---|
| `p-4` / `px-4` / `py-3` | `padding: 1rem` / 左右 / 上下 | 内側の余白（1単位＝0.25rem＝4px） |
| `gap-3` | `gap: 0.75rem` | 並べた部品どうしの間隔 |
| `space-y-2` | 子どうしの上下に `0.5rem` | 縦に並ぶ部品の間隔 |
| `flex` / `flex-col` / `flex-1` | `display: flex` / 縦並び / 残りを全部使う | 並べ方 |
| `items-center` / `justify-between` | 縦の中央 / 両端に寄せる | そろえ方 |
| `rounded-xl` | `border-radius: 0.75rem` | 角を丸める |
| `border` / `border-gray-200` | 枠線 / 枠線の色 | |
| `text-lg` / `text-xs` | 文字の大きさ | |
| `font-bold` | `font-weight: 700` | |
| `text-red-700` / `bg-red-50` | 文字色 / 背景色（数字が大きいほど濃い） | |
| `fixed inset-x-0 bottom-0` | 画面の下に固定、左右いっぱい | 下のタブ |
| `sticky top-0` | スクロールしても上に貼り付く | 見出し |
| `max-w-xl mx-auto` | 最大幅を決めて中央に置く | PC で見たとき横に広がりすぎない |

#### 状態で見た目を変える（バリアント）

`:` の前に条件を書くと、その条件のときだけ効く。

| 書き方 | 効くとき | 使っている場所 |
|---|---|---|
| `active:bg-gray-200` | 押している間 | 日付の ‹ › ボタン |
| `disabled:opacity-40` | `disabled` のとき | 「追加」ボタン（空欄のとき） |
| `focus:border-brand` | 入力欄を選んでいるとき | タスク名の入力欄 |

#### Tailwind にない値を書く

`pt-[env(safe-area-inset-top)]` のように `[]` で囲むと、好きな値を直接書ける（4.8 参照）。

#### 自分の色を足す（@theme）

```css
@theme {
  --color-brand: oklch(0.55 0.15 255);
}
```

と書くと、`bg-brand`・`text-brand`・`accent-brand` が使えるようになる。
アプリのテーマ色を変えたくなったら、ここ1か所を直せばよい。

#### 状態によってクラスを切り替える

```tsx
const box = overdue ? 'border-red-300 bg-red-50' : done ? 'border-gray-200 bg-gray-100' : 'border-gray-200 bg-white'
<li className={`flex items-center gap-3 rounded-xl border px-4 py-3 ${box}`}>
```

共通のクラスはそのまま書き、状態で変わる部分だけを変数にしてつなげる。

### 4.3 API の型を自動で作る（openapi-typescript + openapi-fetch）

```
backend/app/tasks/schemas.py（Pydantic）
   │  FastAPI が API 仕様（OpenAPI）を作る
   ▼
http://localhost:8000/openapi.json（FastAPI が自動で出す。API が起動している必要がある）
   │  npm run gen:api（openapi-typescript）
   ▼
frontend/src/api/schema.d.ts（TypeScript の型）
   │  openapi-fetch に渡す
   ▼
api.GET('/api/tasks', ...) に型が付く
```

```ts
const res = await api.GET('/api/tasks', { params: { query: { date: day } } })
//                         ^ 存在しない URL を書くと型エラー
//                                                  ^ date 以外の名前を書くと型エラー
res.data?.items[0].title   // ← InstanceRead の項目として補完される
```

**サーバーの schemas.py を変えたら `npm run gen:api` を実行する。**
たとえばサーバーで `title` を `name` に変えた場合、画面側で `task.title` と書いている所がすべて型エラーになり、直し忘れを防げる。

#### unwrap：失敗を例外に変える

openapi-fetch は、失敗しても例外を投げず `{ error }` を返す。
一方 TanStack Query は「例外が投げられたら失敗」と判断する。そこで `unwrap()` で「失敗なら ApiError を投げる」に変換している。
ApiError の文言には、FastAPI が返した `detail`（例：「定期タスクの回は削除できません…」）を入れる。

### 4.4 TanStack Query：サーバーのデータの扱い

#### 取得（useQuery）

```ts
const tasks = useTasks(day)   // 中で useQuery({ queryKey: ['tasks', day], queryFn: ... })

tasks.isPending   // 初めて読み込み中
tasks.isError     // 失敗した（tasks.error.message に理由）
tasks.data        // 取れたデータ
tasks.refetch()   // もう一度取る
```

`queryKey` は、キャッシュの名札。`['tasks', '2026-11-07']` と `['tasks', '2026-11-08']` は別のキャッシュになる。
一度見た日に戻ると、キャッシュがあるのですぐに表示される（裏でサーバーに確認し、変わっていれば差し替わる）。

自分で `useEffect` と `fetch` で書くと、「読み込み中の表示」「エラー」「アプリに戻ってきたときの再取得」「古い返事が後から届く問題」をすべて自分で扱う必要がある。それを任せられるのが TanStack Query の価値。

#### 更新（useMutation）と invalidateQueries

```ts
onSuccess: () => qc.invalidateQueries({ queryKey: ['tasks'] })
```

「`tasks` で始まる名札のキャッシュはすべて古くなった」と印を付ける。
表示中の一覧はすぐに取り直され、ほかの日の一覧は次に表示したときに取り直される。

#### 楽観的更新（完了チェック）

外出先の遅い回線で、チェックを押しても1秒反応がないと「押せてない？」と2回押してしまう。
そこで、サーバーの返事を待たずに画面を先に変える。

```
タップ
  │
  ├─ onMutate：キャッシュの done_at を先に書き換える（画面がすぐ変わる）
  │            書き換える前の状態を previous として取っておく
  │
  ├─ サーバーに PATCH を送る
  │
  ├─ 失敗したら onError：previous に戻す（チェックが元に戻る）
  │
  └─ onSettled：成功・失敗どちらでも、最後にサーバーから取り直す
                （期限切れの件数など、画面側では計算していない値もそろえる）
```

### 4.5 React Router：URL と画面

```tsx
createBrowserRouter([
  {
    path: '/',
    element: <Layout />,          // 共通の枠
    children: [
      { index: true, element: <Navigate to="/tasks" replace /> },
      { path: 'tasks', element: <TasksPage /> },   // Layout の <Outlet/> に入る
    ],
  },
])
```

Phase 2 で買い物リストを作るときは、`{ path: 'shopping', element: <ShoppingPage /> }` を足し、
Layout の `<Tab icon="🛒" label="買い物" />` に `to="/shopping"` を付ける。

#### 表示中の日付を URL に持たせる

```ts
const [params, setParams] = useSearchParams()
const day = params.get('date') ?? today
```

`useState` で持つこともできるが、URL（`/tasks?date=2026-11-07`）に持たせると、

- リロードしても同じ日が出る
- ブラウザの「戻る」で前に見ていた日に戻れる

という利点がある。今日を表示するときは `?date=` を付けない（URL がすっきりし、翌日に開いたとき自動で「新しい今日」になる）。

### 4.6 React の部品の書き方

#### props：部品に渡す値

```tsx
<TaskItem task={task} day={day} onToggle={(done) => toggle.mutate({ id: task.id, done })} />
```

`TaskItem` は「何が起きたか」（チェックが変わった）だけを `onToggle` で親に知らせ、
「どう処理するか」（API を呼ぶ）は親の TasksPage が決める。部品を API から切り離しておくと、別の画面でも使い回せる。

#### useState と「制御されたコンポーネント」

```tsx
const [title, setTitle] = useState('')
<input value={title} onChange={(e) => setTitle(e.target.value)} />
```

入力欄の中身を React の state で持つ書き方。`setTitle('')` で入力欄を空にできる。
追加に成功したときだけ空にし、失敗したら打った文字を残すようにしている（再送できるように）。

#### 条件による表示の出し分け

```tsx
{withDue && <input type="datetime-local" ... />}          // true のときだけ表示
{tasks.isPending ? <読み込み中/> : tasks.isError ? <エラー/> : ...}  // 状態で出し分け
```

一覧は「読み込み中・エラー・0件・一覧」の4つの状態を必ず考える。0件のときに何も出さないと、「読み込めていないのか、本当にないのか」が分からない。

#### key

```tsx
{tasks.data.items.map((task) => <TaskItem key={task.id} ... />)}
```

React が「前回の描画のどの行が、今回のどの行か」を見分けるための印。
期限切れが先頭に来るなど並びが変わっても、正しい行を描き直せる。配列の番号（index）ではなく、変わらない `id` を使う。

### 4.7 日時の扱い（lib/datetime.ts）

サーバーは UTC で返す（`2026-11-06T23:00:00Z`）。画面ではすべて日本時間で表示する。

| 関数 | 例 |
|---|---|
| `todayJst()` | → `"2026-11-05"` |
| `addDays("2026-11-30", 1)` | → `"2026-12-01"` |
| `formatDayLabel("2026-11-07")` | → `"11/7(土)"` |
| `formatTime("2026-11-06T23:00:00Z")` | → `"08:00"` |
| `localInputToIso("2026-11-10T18:00")` | → `"2026-11-10T18:00:00+09:00"` |

工夫している点：

- **`Intl.DateTimeFormat` に `timeZone: 'Asia/Tokyo'` を毎回指定**：iPhone のタイムゾーン設定に関係なく、日本時間で表示する
- **`en-CA` で `YYYY-MM-DD` を作る**：カナダ英語の日付の書き方がちょうど `2026-11-05` の形なので、ライブラリなしで作れる
- **日付の計算は正午で行う**：`2026-11-05T12:00+09:00` を基準に足し引きすれば、どのタイムゾーンで計算しても日付がずれない
- **入力欄の値に `+09:00` を付けて送る**：`<input type="datetime-local">` の値にはタイムゾーンがない。サーバーはタイムゾーンなしの日時を拒否する（解説 01 の 4.5）

### 4.8 iPhone 向けの工夫

| 工夫 | 場所 | 理由 |
|---|---|---|
| `viewport-fit=cover` と `env(safe-area-inset-*)` | index.html、Layout | ホーム画面から開くと画面の端まで使う。ノッチやホームバーに見出し・タブが隠れないよう余白を取る |
| `min-h-dvh` | Layout | Safari のアドレスバーの出入りに合わせた高さ。`vh` だと下が切れることがある |
| 入力欄は `text-base`（16px） | AddTaskForm | 16px 未満の入力欄をタップすると、iPhone が画面を勝手に拡大する |
| チェックボックスを `label` で囲む | TaskItem | 文字をタップしてもチェックできる。小さい四角を狙わなくてよい |
| ボタンは `size-11`（44px） | 日付の ‹ › | Apple が推奨する、指で押しやすい最小の大きさ |
| `-webkit-tap-highlight-color: transparent` | index.css | タップしたときに出る灰色の四角を消す |

### 4.9 FastAPI から画面を配信する（backend/app/frontend.py）

React で作った画面は SPA（シングルページアプリケーション）で、HTML は `index.html` の1枚だけ。
`/tasks` という URL のファイルは実際には存在しない。どの画面を出すかは、ブラウザ側の React Router が URL を見て決める。

そのため FastAPI では次のように振り分ける。

| URL | 返すもの |
|---|---|
| `/api/...` | API（存在しなければ 404） |
| `/assets/index-DuEk6gxb.js` | ビルドしたファイル |
| `/favicon.svg` | dist の直下のファイル |
| それ以外（`/tasks` など） | `index.html` |

注意している点：

- **登録の順番**：`/{path:path}` はどの URL にも当てはまるので、API より後に登録しないと API が隠れてしまう
- **フォルダの外を読ませない**：`/../secret.txt` のような URL で dist の外のファイルを読まれないよう、`is_relative_to(dist)` で確かめる（テスト `test_cannot_read_outside_dist`）
- **index.html はキャッシュさせない**：`/assets/` のファイルは中身が変わると名前も変わるが、index.html は名前が変わらない。`Cache-Control: no-cache` を付けて、サーバーを更新したらすぐ新しい画面になるようにする
